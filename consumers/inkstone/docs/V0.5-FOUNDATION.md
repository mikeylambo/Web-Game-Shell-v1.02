# INKSTONE V0.5 — Flagship Foundation

## Authority

V0.5 development lives in the private `mikeylambo/Web-Game-Shell-v1.02` repository on branch:

`integration/inkstone-v0.5`

Inkstone is mounted at:

`consumers/inkstone/`

The public `mikeylambo/Inkstone` repository remains the stable V0.4 release surface until a future release/export step.

The one-time public-to-private bootstrap importer has been retired. This private workspace is now authoritative and cannot be accidentally overwritten by manually rerunning the bootstrap sync.

## Baseline

Last known-good public gameplay baseline:

`mikeylambo/Inkstone@10e1d80c67ae1ac8f4fbf7abd23374fcbb901652`

V0.5 is parity-first. Shell integration must not silently rewrite combat feel.

## CI gates

`.github/workflows/inkstone-integration-ci.yml` requires all of the following:

1. private SLU Shell verification (`npm run verify:base`)
2. Inkstone dependency install against the local private Shell
3. V0.4 feel-source parity (`npm run parity`)
4. Shell lifecycle contract (`npm run test:lifecycle`)
5. Shell persistence contract (`npm run test:persistence`)
6. Shell navigation contract (`npm run test:navigation`)
7. release platform contract (`npm run test:platform`)
8. release certification contract (`npm run test:certification`)
9. production Vite build (`npm run build`)
10. production bundle certification (`npm run certify:build`)
11. packaged V0.5 major-playtest artifact

The source parity gate pins 19 feel-critical files covering combat, player/enemies, animation poses, camera, input, run/RNG/record/score, strokes/glyphs, tuning, VFX and world state.

The persistence gate verifies backup-before-write, payload validation, corrupt-write refusal, primary repair, backup recovery, manual restore and migration of compatible Inkstone options into Shell settings.

The navigation gate audits all 17 current app states, verifies the explicit legal transition graph, walks the current pad-reachable semantic routes, proves critical illegal edges are rejected, and confirms the Shell `ScreenManager` mirror settles on the coordinator's authoritative state.

The platform gate verifies browser capability detection, Shell-owned resize/fullscreen behavior, controller connection lifecycle, WebGL context loss/restoration, player-safe recovery, explicit retry/title paths, degraded-browser warnings and disposal cleanup.

The certification gate makes the accessibility option surface, clean runtime diagnostics, recovery state and real presentation-frame evidence explicit release requirements rather than incidental implementation details.

The bundle gate rejects missing release files, exposed source maps and V0.5 web-bundle size regressions before the tested `dist/` is uploaded as a 14-day major-playtest artifact.

## Navigation rules

- Existing menu buttons still call the same `Game` navigation methods; V0.5 installs Shell authority beneath `Game.setState` without editing the protected V0.4 `game.js` source.
- Every requested state change is checked against the explicit Shell-owned transition graph before Inkstone's existing show/hide behavior runs.
- Illegal transitions fail closed: the current state is preserved, telemetry records the rejection and Studio diagnostics capture it.
- Inkstone's existing `MenuNav` remains the only focus/navigation controller inside each screen. No second focus system is allowed to compete with it.
- `WAVE_CHOICE` may return only to `RUN`; `DEATH`/`MISSION_CLEAR` must pass through `RESULTS`; reserved `PILGRIMAGE` returns to `PLAY_SELECT`.
- The Shell `ScreenManager` maintains the semantic screen/history mirror behind the visual adapters.
- Studio exposes `inkstone.navigation.status` and `inkstone.navigation.audit`.

## Lifecycle rules

- Losing window focus while actively in `RUN` requests Inkstone's existing pause path.
- Hiding the document while actively in `RUN` requests the same pause path.
- The existing `PauseMenu` remains responsible for clearing held input and presenting pause UI.
- Actual `PAUSE` suspends presentation audio.
- Leaving `PAUSE` resumes presentation audio.
- `WAVE_CHOICE` uses a paused Shell phase but does **not** suspend presentation audio.
- Regaining focus never auto-resumes gameplay. Resume remains an explicit player action.

## Persistence rules

- Existing Inkstone localStorage keys remain the compatibility surface during V0.5; the migration does not rewrite the player-facing save schema.
- Shell `SaveManager` stores a versioned compatibility snapshot and preserves a previous known-good envelope before each write.
- A snapshot is rejected if any included Inkstone JSON payload is corrupt. Corruption cannot silently replace the safe copy.
- On boot, missing or corrupt compatibility keys are restored from the newest validated Shell snapshot.
- If the Shell primary envelope cannot be used, the validated backup is promoted to primary **before** any new save, so a corrupt primary cannot overwrite the last-good backup slot.
- Input bindings and PlayerOptions are rehydrated after recovery so repaired values take effect in the same launch.
- Player options remain Inkstone-specific where necessary, while exact semantic matches for master/music/SFX volume and screen shake mirror into Shell `CoreSettings`.
- State changes, run start/finish, page hide and disposal request safe snapshots. Invalid data is refused rather than normalized away.
- Studio exposes `inkstone.save.status` and `inkstone.save.restore` for inspection and deliberate recovery.

## Release / platform rules

- Browser capability detection is explicit. A missing browser environment is a blocker; unavailable fullscreen, gamepad API or persistent storage are reported as degraded-mode warnings rather than hidden assumptions.
- Renderer resize now enters through Shell `BrowserPlatform.onResize`; camera/render math remains Inkstone-owned.
- The existing Fullscreen option remains visually unchanged, but its browser call is routed through Shell `BrowserPlatform`.
- Gameplay input remains Inkstone-owned. Shell observes controller connect/disconnect only as platform lifecycle and telemetry.
- WebGL context loss shows a player-safe recovery surface. Diagnostic detail stays in Studio; players see retry/title choices only.
- Context restoration hides the recovery surface when no fatal runtime condition remains.
- Retry never pretends a still-lost WebGL context recovered. Fatal retry reloads the current build; Title returns through Inkstone's legal app-flow path.
- Shell Studio exposes `inkstone.platform.status`, `inkstone.platform.audit`, `inkstone.release.status`, a Platform panel and a Release panel.
- Dev builds additionally expose `inkstone.recovery.test` so the recovery surface can be checked without manufacturing a real failure.

## Certification rules

- Automated structural certification and human/device certification are different evidence classes and must not be conflated.
- The exact build under test is the `inkstone-v0.5-major-playtest-<commit sha>` artifact from a green workflow run.
- Required accessibility controls are contractually pinned: deadzone, X/Y inversion, shake, hit-stop, flash reduction, camera motion, high-contrast tells, text scale and hold/toggle behavior.
- Live certification fails while a WebGL context is lost, while a fatal recovery state is active, or when Studio has captured runtime errors.
- Live performance evidence requires at least 120 recent presentation-frame samples. Current V0.5 thresholds are mean <= 20 ms, p95 <= 25 ms and sampled average >= 50 FPS.
- `requestAnimationFrame` cadence is sampled independently of the fixed-step simulation; long tab/background suspension gaps are excluded because background behavior has its own lifecycle contract.
- Studio exposes `inkstone.certification.status`, `inkstone.certification.run`, a Certification panel and `inkstone.playtest.snapshot`.
- `docs/V0.5-MAJOR-PLAYTEST.md` is the authoritative human browser/controller/recovery/performance protocol.

## Migration rule

Move one outer responsibility at a time. A responsibility crosses the Shell boundary only when:

1. feel-source parity remains green,
2. its own contract/regression test is green,
3. Inkstone builds against the current private Shell,
4. no protected combat file was changed as collateral work.

Gameplay evolution is allowed, but it must be treated as an explicit gameplay change with a reviewed new baseline rather than hidden inside framework migration.

## Current boundary

The **code-side V0.5 flagship foundation is complete once the current certification head is green**. It should not be declared human-certified until the primary rows in `V0.5-MAJOR-PLAYTEST.md` are actually performed on real browsers/controllers.

After that human pass, the next deliberate gameplay phase is V0.6: Style/Reality evaluation and its axes (Composition, Flow, Variety, Precision/Control), followed later by Pigment and the Finishing Stroke / Scroll-Cut path. Reopening any of the 19 protected feel files for those systems requires an explicit reviewed gameplay baseline update rather than a framework-migration exception.
